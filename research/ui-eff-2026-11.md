## 结论先行

1. **首屏目标已达成**：360px 宽、3 条待审检查点时，第一个「批准」按钮的顶边在 **≈120px**（若宿主没评估过风险、多出一行提示，则 ≈141px），比 200px 的预算还早 80px。
2. 但这条快路径**只有队列给得出**。卡级动作（暂停/继续/停止）在展开卡底部，约 **500–650px**，且要先展开、再滚动、再二次确认：3 次点击 + 约 0.7 屏。这是真正超预算的路径。
3. 面板渲染 **34 条信息**，其中 **5 条过不了效率检验**（战役数/轮数/知识数三个聚合、链行、节点 chips 行），另有 **3 条与别处重复**（`为什么` 行、`meta` 行、队列的「已评估」），**2 条是会话内静态行**（卡头 `age`、页脚 Lean，见 §3.1）。
4. 有 **12 个字段是「变了但没渲染」**：`waitMs`、`openCheckpoints[].at`、宿主 `now`、`workspace`、`policy`/`loop`、每轮 `planMs`/`verifierMs`/`costUsd`、`candidates[]`、`constraints[]`、`autopilot`、`holdout.picks` 等。最贵的是 `waitMs`：它正好回答「这条等了多久」。
5. 三件该停的事：把**聚合当指标**、让**会话内静态行**占首屏、把**同一事实在三处复述**。

## §4 五条提案（按 收益÷成本 排序）

每条给：改什么 / 文件+函数 / 节省 / 一条能失败的断言（沿用 `tests/ui/harness.mjs` 的
`loadPanel()` + `panel.<fn>` 范式，断言写在新的 `tests/ui/efficiency.test.mjs`）。

### P1 · 队列行显示等待时长，并把「暂缓」补进队列

- **改什么**：`pending()` 的 `now` 默认值改为 `data.now`（宿主钟）再退回 `Date.now()`（client:636）；
  队列行（1795–1816）在 `summary` 后加 `· 等 3 天`（`age(q.waitMs)`，293）；1848 后补第三个按钮
  `暂缓`，调用 `act(q.campaign,'decide','snooze',q.id)`——`verbs`（637）与树里的动作（1427）都已支持。
- **文件+函数**：`client/index.js` `pending`（632）、队列渲染（1745–1850）；纯函数建议抽出
  `queueRowText(q)` 返回 `{ campaign, kind, summary, wait, assessed, deferred }` 的可断言投影。
- **节省**：暂缓从「展开卡 + 滚 ≈400px + 点树里的暂缓」（3 次点击）变成 **1 次点击**；
  等待时长从「点开卡片看 `age`」变成 **0 次点击**。队列排序不变。
- **断言**：
  ```js
  const p = panel.pending({ now: 10000, campaigns: [{ id: 'c1', openCheckpoints: [{ id: 'cp1', kind: 'promote', at: 1000 }] }] })
  assert.equal(p[0].waitMs, 9000)                    // 用宿主 now，不用浏览器钟
  assert.ok(p[0].actions.includes('snooze'))          // 队列与树动作集合一致
  assert.match(panel.queueRowText(p[0]).wait, /秒|分|小时|天/)
  ```

### P2 · 卡头带 暂停/停止，折叠态也能停

- **改什么**：新增纯函数 `cardActions(c)` → `[{ key: 'pause'|'resume', label, title }, { key: 'stop', … }]`；
  渲染进 `.loom-titlerow`（2003–2011，`loom-name` 右侧、`loom-age` 之前），`stop` 保留二次确认；
  底部 `.loom-acts`（2198–2253）只留「收起」。
- **文件+函数**：`client/index.js` `Card`（1992）、新增 `cardActions`（放 1219 附近纯函数区）。
- **节省**：停止路径 3 次点击 + ≈0.7 屏滚动 → **2 次点击 + 0 滚动**；每张展开卡还省下底部 27px。
- **断言**：
  ```js
  const run = panel.cardActions({ status: 'running' })
  assert.deepEqual(run.map(a => a.key), ['pause', 'stop'])
  assert.deepEqual(panel.cardActions({ status: 'paused' }).map(a => a.key), ['resume', 'stop'])
  ```

## §5 三件该停止做的事

1. **停止把聚合当指标。** 战役数、轮数合计、知识总数（534/536/541）都不能改变一个决定：
   前者与下方列表同义，中者跨战役不可加，后者只增不减。聚合只有在**触发动作**时才是指标
   （待处理 → 去批；未定价 → 去定价；隔离 → 去解除），否则只是让首屏多三格。

2. **停止让会话内静态的行占据首屏。** 链行（2194）与页脚「本窗口驱动 / Lean 就绪」（1972–1977）
   在整个会话里几乎不变，却分别吃掉每卡 17.5px 和常驻 28px。它们该在 `title` 里，
   或者只在变化时出现（例如 Lean 未安装时才提示）。

3. **停止同一事实三处复述。** 轮状态出现在 `为什么` 行（1396）、轮次行（1379）和 `meta` 行
   （2110）；检查点出现在队列（1776）、树（1403）和 `待 N` 徽标（2029）；知识同时出现在
   卡片树的「知识」分支（1448）与底部知识区（1852）。复述不是冗余保险——两处渲染一旦分叉，
   面板就会同时说两句不同的话。
