## §0 结论（先看这 5 行）

1. 面板在「谁在等我」这件事上**有一个静默失效字段**：`client/index.js:1075` 与 `client/index.js:1311` 把 `openCheckpoints`（数组）当计数用，`Number([]) === 0`、`Number([{}]) === NaN`，于是折叠卡的「待 N」永远不渲染、默认展开也永远落不到等待中的战役。而 `src/panel/api.js:105` 早就把 `open`（纯计数）发过来了，注释还写着「`open` stays a numeric count for the badge」。
2. 待办队列**没有等待时长**，且动作比卡片树里少一个（队列只有 批准/驳回，树里是 批准/驳回/暂缓）；`openCheckpoints[].at` 已发给前端但全文件从未读取（`src/panel/api.js:110`）。
3. 键盘与读屏基本不可用：全文件 `onKeyDown|onKeyPress|onFocus|onBlur` 命中 **0 处**，`aria-*` 只有 3 处（`client/index.js:1044`、`:1547` 与 `:1317` 的 `role='button'`）。
4. 同一事实有两套表示（知识 4 条 vs 3 条、`attemptChips` 是导出并测试过的死代码），且颜色一层承担 6 种语义、JS 里散落 10 处裸 hex。
5. 最高性价比的 5 件事全是「删噪 + 接线」，不是加装饰：修徽标、去裸 hex、队列补时长/第三动作、button 化、spark 补 0 基线。**预计新增 ≤150 行、净删 >40 行（U6），且不引入任何新依赖。**

## §1 现状诊断（5 个具体问题，带行号/选择器证据）

### 1.1 【P1｜信息丢失】折叠卡的「待 N」与「默认展开」双双失效：数组被当计数

- `client/index.js:1311`：`var openCp = Number(c.openCheckpoints) || 0`
- `client/index.js:1075`：`return c && !c.error && c.openCheckpoints > 0`
- `src/panel/api.js:105-107`：`open: open.length`（计数）+ `openCheckpoints: open.map(...)`（数组）；`:34-35` 注释明确「`open` stays a numeric count for the badge」。
- JS 强制转换：`Number([]) === 0`；`Number([{…}]) === NaN`；`NaN > 0 === false`。

后果（两条，都是「面板在最该说话时沉默」）：

1. 折叠态（`client/index.js:1307-1326`，注释自称「what it is, where it stands, and **whether it wants something from the reader**」）在 `openCp > 0` 时才渲染 `待 N`（`:1321`），而 `openCp` 恒为 0 —— 一屏里 N 个折叠战役**没有一个**会显示「有人在等你」。
2. `attention`（`:1072-1081`）先找「有开放检查点」的战役，然后才退到 `running`。第一支分支永不命中，默认展开永远落到「最近在跑的那一个」，而真正要人拍板的那个被折成一行。

这条缺陷**任何几何审计都测不出来**：`scripts/panel-audit.mjs` 量的是溢出、对比度、列数、发丝线、阴影，量不出「一个字段恒为 0」。这正是 §4 要求纯函数断言的原因。

### 1.2 【P2｜队列缺三样东西】没有等待时长、少一个动作、风险只到第 3 条

- 队列渲染 `client/index.js:1116-1157`：一行 = `loom-dot`（颜色=risk）+ `战役 · 检查点类型 — summary` + `批准`（`:1127-1138`）+ `驳回`（`:1139-1156`）。
- 等待时长：`pending()` 在 `client/index.js:432` 写的是 `ageMs: c.ageMs` —— 这是**战役最近活动时间**，不是检查点创建时间；真正的检查点时间戳 `at` 由 `src/panel/api.js:110` 发出，客户端**从未读取**（全文件只有 `c.openCheckpoints || []` 与上面的数组误用）。
- 动作数：卡片树 `waitingNode`（`client/index.js:813-817`）给三个动作 批准 / 驳回 / **暂缓**（`decision: 'hold'`）；队列只给两个。同一个检查点，从队列看是「二选一」，展开卡片才变成「三选一」。
- 风险只到第 3 条：`src/panel/api.js:36-38` 每战役只带 `reviewQueue(s).slice(0, 3)`；`pending()` 在 `client/index.js:430` 对找不到 review 的检查点回落到 `'normal'`。一个战役第 4 个及以后的检查点会被**静默降级为普通**，排序上沉底。
- 附带：`summary` 同时进 `title` 和正文（`:1122-1125`），正文是单行省略（`.loom-row .txt`，`client/index.js:120`），即在 320px 下摘要几乎只存在于 tooltip 里 —— tooltip 是键盘/触屏拿不到的信息通道。
- 树里给得出的数字（`payload.verdict` / `Δ` / `taskId`，`:802-806`）在队列行里全部消失。

### 1.3 【P3｜键盘与读屏不可用】全文件 0 个按键处理器，3 个 aria 属性

`grep -n "tabIndex|role:|aria-|onKeyDown|onKeyPress|onFocus|onBlur" client/index.js` 的完整结果只有 3 行：

```
1044:  'aria-label': '刷新',
1317:  { className: 'loom-hit', onClick: ..., role: 'button', tabIndex: 0 },
1547:  'aria-hidden': 'true',      // 侧栏图标
```

- 折叠行 `:1317` 声明了 `role='button'` 与 `tabIndex: 0`，但**没有 `onKeyDown`** —— Tab 能聚焦，Enter/Space 什么也不会发生。
- 展开态整卡的点击区是一个 `div`（`:1442` 起，`onClick` 包住 head/obj/vitals/tri/meta/chain，约 `:1447`），**没有 `role`、没有 `tabIndex`** —— 鼠标之外没有第二条展开路径（只有卡片底部「收起」按钮可达，`:1499` 附近）。
- 只有两处 `:focus-visible`：`.loom-btn`（`client/index.js:87`）与 `.loom-switch`（`:97`）。`.loom-hit` 只有 `:hover`（`:138`），树行 `.loom-node` 只有 `:hover`（`:200`）—— 键盘用户看不到焦点在哪。
- 无 `aria-expanded`（折叠/展开状态对读屏不可见）、无 `aria-live`（5 秒轮询后队列变化不播报）、无 `aria-pressed`/`aria-selected`。

### 1.4 【P4｜同一事实两套表示】「知识」出现两次、上限不同；一个被测试覆盖的导出是死代码

- 卡片树里的「知识」：`lessonsNode`（`client/index.js:837-854`）读 `c.lessonsTop`，每组 `top.slice(0, 3)`（`:844`），挂在 `treeOf` 的固定四段 `round → wait → live → lessons`（`:856-867`）。
- 面板底部又有一整块「知识」：`treeBlock`（`:1161-1196`）读 `knowledge()`，`client/index.js:469` 每组 `items.slice(0, 4)`，并按 `score` 排序。
- 两处都用 `c.lessonsTop`（`:838`、`:457`），总数也一样（都来自 `num(c.lessons)`，`:843`、`:455`），但**呈现不同**：卡片内是不分 kind 的 3 条平铺（`:844`），底部是按 fact/hazard/recipe 分组、每组 4 条（`:469`），标题一个是 `知识 + 总数`、一个是 `N 有效 · M 隔离`（`:1171`）。同一个词、同一批数据、两种分组与两种上限。
- `attemptChips`（`:725-733`）被导出（`:1580`）也被测试覆盖，但渲染路径走的是 `lastRoundNode`（`:767-791`），函数**在产品里不可达**。测试给了它「已验证」的假象。

### 1.5 【P5｜编码层会撒谎】spark 的 2px 基线、单色系承担 6 种语义、10 处裸 hex

- spark：`client/index.js:172-174` 给 `.loom-spark .pt` `min-height:2px`；`sparkOf`（`:635-662`）柱高 = `2 + Math.round(share * (SPARK_PX - 2))`（即 `2 + round(share*11)`）。于是 `score = 0`（失败）与 `score = null`（无分）在柱上**完全同形**，都是 2px；8 根柱里「有分但很小」也被 2px 下限压平。而 `triangleChips` 另有一套「没有数据」的表达（`measured === false` → 单个 quiet chip「未测量」，`:550-600` 附近）—— 同一个面板里两套「无数据」语言。
- 颜色：`client/index.js:66` 定义 4 个语义色 `ok #3d8a58 / warn #8f7a33 / bad #c05a4a / idle #7a7f87`，却被用来表达 ≥6 种谓词：状态（`:304-308`）、质量（`:311-315`）、风险（`:743`）、验证结果（`:780`）、晋升与否（`:788`）、meter 水位（`:664-681` 的 tone）。待办队列里的「高危」与预算「已满」同色，读屏与色觉障碍用户拿不到区分（WCAG 1.4.1 要求不单靠颜色）。
- 裸 hex 绕过 token：`:305`、`:307`、`:312`、`:314`、`:743`、`:780`、`:788`、`:829`、`:832`、`:1188` 十处在 JS 里直接写 `#3d8a58` / `#c05a4a` / `#8f7a33`。`paintInk()`（`:271-281`）本来就是为了让面板跟随宿主主题（把 computed color 写进 `--loom-ink-base`），这十处颜色会**在浅色画布上保持深色主题的取值**，而 `docs/panel-preview.html` 的 light 400px 画布正是审计在测的场景。

## §3 案例解剖（6 个，含一个同宿主邻居）

### 3.1 Linear：密度是「删噪 + 位置可预测」，不是缩小字号

- 解决什么信息问题：功能一个个加进来后，界面被挤变形；动作位置漂移导致每次都要重新找。
- 手法：重定基础层（hierarchy / balance / density），Inbox 明确「increased density」，sidebar「less cluttered」；三个月后的复盘写的是「修剪 edges」，并举例 header bar 里 share / copy / PR 的位置以前**不可预测**。全局 chrome 用 inverted L-shape（左侧栏 + 顶栏是一体的），每屏先做完整流程再收敛。
- 借到我们哪：`header`（`client/index.js:1032-1049`）与卡片头部字段序（`:1299-1305`：dot → 名称 → 状态 → age → caret）已经是固定序，**要保持并在 DESIGN.md 里锁死**；密度增益应来自删重复表示（§1.4）与折叠态承载更多字段，而不是把 9px 再缩小。
- URL：<https://linear.app/changelog/2024-03-20-new-linear-ui>、<https://linear.app/now/how-we-redesigned-the-linear-ui>、<https://linear.app/now/behind-the-latest-design-refresh>

### 3.2 GitHub Actions：等待人工是一个**有名字的状态**，两个动作、后果写清、会超时

- 解决什么信息问题：一个 job 卡在「等人批」，界面必须让人一眼认出它不是在跑，而是在等。
- 手法：状态就叫 **"Waiting"**；审查入口叫 Review deployments，可以先留评论再 Approve and deploy / Reject，且**写明 Reject 会让 workflow 失败**；30 天不批自动失败（有界等待）。
- 借到我们哪：`待你处理` 队列（`client/index.js:1105-1159`）现在只有颜色点 + 两个无后果说明的按钮。应把「等待 N 分钟/小时」放进行内、把「驳回会让这一轮作废」写进按钮 title（`驳回` 已有二次确认 `:1145`，缺的是**后果文本**），并给「暂缓」一个明确语义（等同 GitHub 的 wait timer，而不是静默消失）。
- URL：<https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/review-deployments>

### 3.3 Sentry：「待审」是 unresolved 的子集，单独一个流；每行三件事；排序策略可选且可解释

- 解决什么信息问题：几百条问题里，哪条需要我处理、哪条只是背景噪音。
- 手法：`For Review`（`is:unresolved is:for_review`）是 unresolved 的**子集视图**，不混在主列表里；每行固定显示「类型与描述 / 所属项目 / 时间（first seen、last seen）」；排序可在 Recommended / Last Seen / First Seen / Trends / Events / Users 之间切，Trends 的排序规则公开（相对量、绝对量、以及**每 12 小时折半的年龄衰减**）。
- 借到我们哪：我们的队列已经是「跨战役的待审子集」（`pending()`，`client/index.js:409-440`），方向对；缺的是**排序理由可见**与**时间字段**。借它的「每行三件事」，队列行应为：`风险词 + 战役 · 类型` / `等待时长` / `摘要（可换行 2 行，不只 title）`。
- URL：<https://docs.sentry.io/product/issues/>、<https://docs.sentry.io/product/issues/states-triage/>

### 3.4 Grafana 表格：时间序列压进单元格，一行同时给「现在」和「趋势」

- 解决什么信息问题：概览表要在一屏里看很多变量的当前值和走势，不能为每个变量画一张图。
- 手法：`TableCellDisplayMode` 里有 `sparkline`，配合 cell 的彩色文本 / gauge / 色块；官方教程的说法是「many variables at a glance」，并强调先做 Reduce 转换把区间值收成一行。
- 借到我们哪：我们已经有 spark（`client/index.js:1344-1358`）和 meter（`:1360-1372`），但它们在展开卡里各占一行。可以合成**一行两列**（左：8 轮段条 + 首末轮号；右：预算 2px 条 + `3/12` 数字），展开卡高度省 ~18px，且段条天然带 0 基线。
- URL：<https://grafana.github.io/grafana-foundation-sdk/go/Reference/common/object-TableCellDisplayMode/>、<https://docs.enlyze.com/en/integrations/grafana/visualisation-types/03-tables>

### 3.5 Raycast Action Panel：动作是**列表**，不是散落的按钮；每个动作标出快捷键

- 解决什么信息问题：一个条目有 8 个可用动作时，全画成按钮会淹没内容；不画又发现不了。
- 手法：`⌘K / Ctrl K` 打开该条目的完整动作面板，**每个动作右侧显示它的快捷键**，让用户从「每次按 ⌘K」过渡到「直接按快捷键」。
- 借到我们哪：卡片树里每个检查点有 3 个动作（`client/index.js:813-817`）、卡片底部有 4 个（暂停/继续/停止/收起）。应把它们收进「选中行 → 动作面板」：`Enter` 执行首选（批准），`Esc` 关闭，动作右侧标 `A` / `R` / `H`。这同时解决 §1.3 的键盘路径与 §1.2 的动作不一致。
- URL：<https://manual.raycast.com/action-panel>

### 3.6 同宿主邻居：`@nanmicoder/dsh-agent-teams` 的活动面板（388px 默认、320 最小，**和我们在同一个侧栏里**）

## §5 反例清单（明确不该做什么）

| # | 不要做 | 为什么（不是审美偏好） |
| --- | --- | --- |
| 1 | 加渐变 / 发光 / 玻璃拟态 | 面板用 `color-mix` 单色 + 4 语义色是**为浅色/深色双画布**准备的；渐变在两种 base 下无法各自成立，且审计的对比度是按实色合成背景算的，渐变会让 4.5/3.8 的下限失去意义。OpenDesign 反 slop 清单明确列出「紫渐变 hero」「glassmorphism」(<https://opendesign.cc/skill.md>) |
| 2 | 用 emoji 当图标（✅ ⚠️ 🔴） | 字体回退不可控（Windows/macOS/Linux 三套字形），彩色 emoji 会把 4 色语义体系打穿；同类清单里已列为反模式。现用的 `⌄ / › / ├─` 是文字字形，可保留但要在 CSS 里锁 `font-family: var(--loom-mono)` |
| 3 | 把树改成缩进列表（去掉竖轨 + 肘线） | 层级是「等待/进行中/知识」三段并列，缩进列表在 320px 下会损失「谁属于谁」的唯一线索（`:201-216` 的 `:before/:after` 是这条线索的全部实现）；缩进列表还会让 depth3（43px）吃掉可读宽度 |
| 4 | 给卡片加阴影 / 把圆角加到 12 | 320px 侧栏没有余量养阴影：`shadows > canvas 数` 已是审计的 FAIL 条件（`scripts/panel-audit.mjs:232`），12px 圆角已被测试禁止。Linear 参考里确实有 `lg:12` + 三条阴影，但那是浮起卡片，我们的场景是嵌在侧栏里的常驻列表 —— **这是主动裁剪，别再「补回参考值」** |
| 5 | 在 320px 里塞 SVG 依赖图 | 邻居面板的 DAG 是 388px 起、可浮动到 640px 才有空间放节点（`ActivityPanel.js:231-234`：compact 节点宽 164 起步）。我们的战役层级是线性链（`chainPath()`，`:475-491`），用文本路径表达即可；画图只会把 `panel-audit.mjs` 的 `hScroll` 断言打红 |
| 6 | 加骨架屏 / shimmer 加载态 | 5 秒轮询下每 tick 都闪一次，属于「用动效伪造进展」；现有 `正在读取 ~/.dsh/loom…`（`:1200`）是**只在首次加载**出现的纯文本，正确。要补的是**刷新失败时的错误态**（`:1202` 已有 `loom-err`），不是占位动画 |
| 7 | 把时间改成「刚刚 / 一会儿前」 | 面板服务的是一次明确的判断（等了多久要不要处理它）；模糊词把可比较量变成不可比较量。`age()`（`:293`）输出 `3 小时`/`12 分` 的离散单位是对的，**不要**加「前」以外的修饰，也不要用相对时间库 |
| 8 | 把唯一信息放进 `title` tooltip | tooltip 键盘（多数实现不可触发）与触屏都拿不到；`summary`（`:1122`）与折叠卡 `brief`（`:1322`）现在都依赖 `title` 承载完整信息 —— 正文必须能独立成立 |
| 9 | 只靠颜色区分风险 | 4 色承担 6 义（§1.5）已经超载；风险必须同时给**词**（`高危/普通`）或**形状/位置**（dot 大小、行内前缀）。WCAG 1.4.1 要求不单靠颜色，审计的对比度测试也不会替我们抓这个 |
| 10 | 为了「一屏更多」把 9px 缩到 8px | 审计的下限是 fontSize<13 时对比度 ≥3.8（`scripts/panel-audit.mjs`），8px 在 320px 下的可读性没有规范支撑，且已有 8 档字号挤在 4px 区间；要更多信息应删重复表示（U6）、合并行（U5），不是缩字 |

## §6 落地顺序与验证载体

1. **先做 U1 + U2**（<15 行）：这两条是「静默失效」与「主题漏点」，越晚成本越高；改完立刻跑 `node --test tests/panel-client.test.mjs`。
2. **再做 U3 + U4**（<80 行）：需要把 `Panel` 的纯渲染部分抽出来（现在 `Panel` 直接调 slot/hook，测试只能走 `panel-view.test.mjs` 的 loader 重放）；抽取时保持 `Card` 的 props 形状不变，否则现有断言会碎。
3. **U5 / U6 / U7 可并行**：U6 是净删除，先删再加，避免两套数字同时存在。
4. **像素级回归**：`node scripts/panel-audit.mjs`（三画布 320/400/720）。它守的是「没有横向滚动、没有未 clamp 的溢出、对比度过线、≥640 有 2 列、<360 只有 1 列、≥380 知识 2 列」；**它守不住语义**（U1 就是它漏掉的），所以 §4 每条都必须有 `tests/panel-client.test.mjs` 的纯函数断言兜底。
5. 不建议本轮改动：`docs/panel-preview.html` 三画布结构、`scripts/panel-audit.mjs` 的阈值（主代理正在跑战役，改审计会污染基线）。
