## 3. 只有实战才暴露的五个缺陷（都已修，都有规格）

接线完成后的第一轮真实使用，暴露的问题比规格写的时候多：

1. **渲染器读错字段**：`renderReport` 读 `passage.text`，而抽取器返回 `{passage, matchedTerms, score}` → 任何真的找到段落的 run 都抛 `TypeError`。此前的规格没抓到，因为它所有 fixture 都没匹配到词。修：在 `run.js` 边界归一成 `{text, …}`。规格 7→8 条。
2. **封存报告没有 claim 判定表**：读者拿到一份报告，无法分辨哪句已核。修：报告渲染 `## Claims` 表，manifest 带 `claims[]`。规格 5→6 条。
3. **一个共享名词 + 任意否定词 = "矛盾"**：第一次真实 sink 产生 7 张假矛盾卡（README 编辑、editable install 都被判成和 reward-hacking 结论冲突）。修：要求两个共享内容词，或其中一个本身是极性词。
4. **还是不行 → 矛盾必须点名**：把否定窗口缩到 ±1 后仍误判（"选 agent 有两个预算" 对上 "soak verifier 睡 380 秒"）。政策改为：只认 `claim.contradicts` 显式点名的 lesson id，`tensionsWith` 降级为 advisory，不再产生卡。规格 7→8 条，含两条真实回归配对。
5. **一个死链吃掉整个读预算**：R2 首次 run 的 12 个来源里 4 个最高分的全 404（付费 PDF、huggingface 页面），可读的那篇排在截断线下面一位，报告于是说"什么都找不到"。修：尝试队列 `max(fetchTop*3, fetchTop+4)`，失败的抓取把名额让给下一个候选，报告 header 记 `N read attempt(s)`。规格 7→8 条。

另外新增 `scripts/research-replay.mjs`（+ 7 条规格）：它重算封印、重哈希每个证据 blob、打印 claim 表，并且**不重新抓取来源**（重抓证明的是今天的页面，不是当初引用的字节），**不改写判定**。

## 4. 从 3DGS skill 借来的那部分（`note.js`）

`jaccen/Awesome-Gaussian-Skills` 的 `evidence-workflow.md` 给了五条可机械检查的纪律，`note.js` 把它们变成了 `gradeNote()` 的 finding code：

| 纪律 | 错误码 |
| --- | --- |
| 三档读法（metadata / abstract / full），摘要级不许断言机制与实验 | `depth-exceeds-reading` |
| 锁定身份与版本；"一个可访问的 ID 只证明记录存在" | `identity-{title,authors,identifier}` |
| 作者主张与读者推断分开标 | `claim-type`（六类枚举） |
| 增量必须取同一协议下的两个格子并显式算差 | `delta-{unpairable,protocol,mismatch}` |
| gap 按 scope 记 | `gap-{scope,text}` |

22 条规格（`tests/self45/`），CLI `node scripts/check-note.mjs <note.json>`。

## 5. 这轮**没做**的

- 没有把八个方向做成"自动迭代到饱和"。R8 说停靠饱和规则，而 `run` 仍是固定查询计划即停。
- 没有合并 kg（`research/kg/store.sqlite`，1523 节点）与 `knowledge.json`（47 条）——两套沉淀仍并存。
- 没有把 research 结论自动接进 gate 或 chain 提案：`sink` 写 lesson 与提案卡，仍要人批准。
- 五份之后的方向（R2/R3/R4/R5/R6/R7/R8）都只跑了 standard 档，没跑 deep；每份 2–4 条 claim，不是综述级的穷尽。
