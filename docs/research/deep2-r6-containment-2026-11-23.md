第二层是动作空间，它解释了为什么 agent 比聊天模型危险一个量级。`2210.03629` 那句是全部讨论的分界线：「The idea of ReAct is simple: we augment the agent's action space to」(§2 ReAct : Synergizing Re asoning + Act ing)，而新加进去的那一半是「in the language space, which we will refer to as a thought or a reasoning trace」(§2 ReAct : Synergizing Re asoning + Act ing)——语言动作不碰环境，所以注入在纯对话里最多是一段坏文本，一旦语言动作接到工具上就变成执行。`2302.04761` 把选择权明确交给模型：「The LM should not lose any of its generality and should be able to decide for itself when and how to use which tool」(§1 Introduction)，代价是工具选择成为可攻击面，而且这个面很稀疏：日历工具「is only used for 0.2% of all examples」(§4.2.5 Temporal Datasets)，稀疏事件平时不触发告警。规模上 `2307.16789` 的做法是「we collect a high-quality instruction-tuning dataset ToolBench」(§1 Introduction)，标题写明一万六千余个真实 API；`2305.15334` 要模型「select from a large, overlapping, and changing set tools expressed using their APIs and API documentation」(§1 Introduction)——注意 overlapping 与 changing 这两个词，工具集合本身在动。于是 `2504.19793` 直接打选择环节：污染工具文档就能改变工具选择，效果「outperforms other prompt injection attacks」(§VII Conclusion and Future Work)。`2403.02691` 把这个面固化成 17 条用户指令 × 62 条攻击者指令、30 个 agent 的基准(§1 Introduction)。更早的两篇是这个面的入口命名：`2211.09527` 给出「We define goal hijacking as the act of misaligning the original goal of a prompt to a new goal of printing a target phrase」(§1 Introduction)，`2310.12815` 给出「We propose the first framework to formalize prompt injection attacks」(§1 Introduction)，并用「we conduct quantitative evaluation on 5 prompt injection attacks using 10 LLMs and 7 tasks」(§1 Introduction)把它做成可复现的横截面。

第三层是测量，度量单位选得很单一。`2403.02691` 明说「we use the attack success rate (ASR) as the primary metric」(§3.1 Experiment Settings)，并自称「the first benchmark for indirect prompt injection attacks targeting tool-integrated LLM agents」(§6 Conclusion)。`2410.02644` 把攻击面按运行步骤铺开：「ASB covers various attack and defense types targeting each operational step of LLM-based agents, including system prompt, user prompt handling, tool usage, and memory retrieval」(§1 Introduction)，覆盖 DPI、IPI、记忆投毒、backdoor 与混合攻击。`2306.05499` 在 36 个真实服务上报出「registers an 86.1% success rate in launching attacks」(§1 Introduction)——这个数字之所以重要，是因为它说明攻击的门槛低到不需要优化。`2504.18575` 做了同方向的端到端基准，其结论里有一条反直觉的：「Counter-intuitively, we observe some of our highest ASR-intermediate」(§Mitigations.)。`2402.04249` 在这批里只落下一段立场陈述，讲标准化红队与稳健拒答，没有结果数字(§1 Introduction)。这一支的通病是分母：量的是"攻击成没成"，而"任务还做不做得成"只在少数几篇里出现。

第四层是防御，清楚分成两派，成本模型完全不同。确定性的那一派不信模型：`2503.18813` 靠能力策略「By enforcing capability-based security policies, CaMeL effectively prevents unintended data flows and actions」(§Defeating prompt injections with software security.)，目标限定得极窄「The primary goal of CaMeL is to stop prompt injection attacks coming from untrusted data sources」(§3 Threat Model)，而且它自己论证了"双 LLM 就够"不成立——被污染的会议记录仍能操纵有权限的 planner(§Is Dual LLM of Willison enough?)，代价是解释器要把 P-LLM 重试到「up to 10 times」(§Error handling.)。`2504.11703` 把这条路线写成原则：「security requires deterministic enforcement that holds regardless of how the LLM reasons, even under adversarial influence」(§Challenges for Securing AI Agents)，并给出可组合的安全方向「Narrowing is safe, since it only removes permissions」(§Deterministic Control of Policy Expansion and Narrowing)。`2403.04960` 用非 LLM 的 hub operator 做同样收口：「We design the operator as a non-LLM module to deterministically control interaction with other modules of the hub」(§IV-A 1 Hub operator)，另外还设计了原始字符串共享的权限模型(§IV-C 3 Screening and assistance with screening of messages)。`2505.23643` 把策略挂到会触发后果的工具上：「For tools that can trigger consequential actions, we enforce policy P-T, which prevents the action from being triggered by a prompt injection」(§Assigning policies to tools.)。另一派把防线放回模型：`2404.13208` 用系统 > 用户 > 第三方工具输出的权限序来训练(§What Types of LLM Attacks Exist?)；`2507.02735` 在训练时「we introduce randomized injection position during training」(§1 Introduction)，立下的规范是「A useful prompt injection defense must provide both security and utility」(§2 Preliminaries)。中间还有纯检测一派：`2507.15219` 在 AgentDojo 四个环境上评估(§4.1 PromptArmor vs. Existing Defenses)，攻击集含 Ignore Previous Instructions 与 System Message 一类词汇型注入；`2605.26497` 把这派的整体位置说清楚了：「A first wave of defenses operates at the natural-language reasoning surface」(§1 Introduction)，并主张系统级拦截，代价是承认同源污染仍会失效(§5 Discussion and Conclusion)。

第五层是自适应攻击，它把上一层的分歧从立场问题变成经验问题。`2510.09023` 的开场就是方法论指控：「The best attacks against a computer system or cryptographic protocol are rarely found through purely algorithmic means」(§2 A Brief History of Adversarial ML Evaluations)，结果是「we study 12 recently proposed defenses」(§5 Experiments)并逐条破掉，MELON 的双跑检测被单列(§5.4 Secret–Knowledge Defenses)，触发条件用 RL 搜出来(§4 General Attack Methods)。`2603.13026` 把同一结论说成评估学问题：「defenses reporting near-zero attack success rates can be significantly or even completely broken when evaluated against adaptive attackers」(§1 Introduction)，方法是 GRPO 加动态优势加权(§3.3.2 Dynamic Advantage Weighting)，它的问题清单里明确要求「simultaneously maintain task utility and resist PISmith」(§4 Evaluation)。分类器这一侧被单独打掉：`2605.17634` 报「Prompt injection classifiers perform at near-chance (AUROC 0.43–0.59) when attacks operate through context manipulation rather than injection vocabulary」(§1 Introduction)，语料是 4,200 组配对邮件(§3 Limitations of Current Views on Prompt Injection)，另有 100 个场景、50 个域的并发信息流实验(§6.3 Simultaneous Information Flows)。供应链一侧由 `2403.03792` 补上：执行触发器可以被优化出来，开源模型受害最重(§7. Conclusion and Future Work)。`2307.15043` 只落了 §6 伦理段，但它那句"模型开始自主行动后风险会变大"的预判正好是这批后面所有论文的前提。

最后十篇压在系统与运行时这一层，也是离"怎么造循环"最近的部分。`2603.19469` 指出旧定义漏掉语境：「many existing definitions of security attacks fail to capture this contextual nature」(§1 Introduction)，并把 agent 建模成动作-观测对构成的轨迹(§2 Background on LLM Agents)。`2604.23338` 给出两个可直接抄进设计的判断：「Most agent implementations implicitly treat environment inputs as high-trust」(§2.2.2 The Principal Hierarchy and Trust Inversion)，以及「The escalation emerges from the semantic composition of those authorized actions, and it is invisible to capability-based access control systems that evaluate permissions per-call」(§3.4.2 Capability Creep and Privilege Escalation)，落点是「The minimal footprint principle」(§5.1.3 Tool Sandboxing and Least Privilege (L4, L6))。`2607.05120` 把"数据被当指令"拆成可观测机制：「ADI causes untrusted data to be misinterpreted as trusted data」(§I Introduction)，证明输出侧护栏「ineffective against ADI」(§V Effectiveness of ADI against Defenses)，并能「fabricate an entire tool execution history」(§IV-C Supply Chain Attack via Tool Call and Response Injection)，在 AgentDojo 的 96 条用户任务上评估(§VI-B 1 Evaluation Setup)。`2602.09345` 把成本摆出来：「OS execution accounts for 55–60% of latency with a memory peak-to-average ratio of 15.4」(§7. Conclusion and Future Work)，负载是秒级突发、GB/s 级变化率且不可预测(§4.2. Responsiveness Mismatch)，执法靠 eBPF(§5. AgentCgroup Design and Implementation)。`2503.18666` 给出运行时监控的形状：「The predefined and general enforcement actions consist of the following」(§3.2. Triggers, Checks, and Enforcements)，其中包含 user_inspection 与 llm_self_check，监控挂在事件流上(§3.3. Semantics)。评测侧 `2602.03117` 认为静态任务测不出可部署性，自己给「an open-ended sandbox similar to the AgentDojo framework」(§3.1 Overview and Structure)；`2602.10453` 综述 41 篇后直说「current tasks are predominantly static and lack context-dependence」(§5 Benchmarks & Metrics)，并警告「Some defenses' design will destroy the agents' utility ability to solve context-dependent tasks」(§4.6 Analysis: Defense Cost)；`2601.11868` 是唯一有真实工程栈的：「Terminal-Bench evaluates whether agents can perform the kind of high-skill work that professionals are paid to do」(§1 Introduction)，Harbor 加容器、用 LLM-judge 做命令级错误分析(§4.5 Command-Level Error Analysis)。架构侧 `2504.20984` 的三阶段隔离顺带批评了邻居：「IsolateGPT also trusts app outputs and passes them to the context of execution manager LLM of the hub without any prior verification」(§III-B New Attacks against IsolateGPT)。更早的两篇提供环境建模：`2307.13854` 把环境写成状态/动作/观测/转移四元组(§2.1 Controlling Agents through High-Level Natural Language)，观测要支持多标签(§2.3 Observation Space)、动作要支持复合键鼠(§2.4 Action Space)、还要模拟用户角色(§User Role Simulation)；`2112.09332` 把权限收到最紧：「the only interactions with the outside world allowed by the environment are sending queries to the Bing API and following links that already exist on the web」(§6.5 Risks of live web access)。`2204.05862` 与 `2308.11432` 是校准与协议背景：前者说「we do not expect that our PMs are so robust」(§4.2 Robustness Experiments)，后者把评测协议按真实世界模拟分类(§4.2 Objective Evaluation)。

## 二、我认为什么变了

1. **我们的 lesson 通道就是一个标准的 indirect prompt injection 入口，而且渲染时把来源抹掉了。** `2302.12173` 的原话是检索「blurs the line between data and instructions」(§1. Introduction)，而 `src/dispatch/brief.js:196-201` 把每条经验渲染成 `- [${kind}] ${claim}`，kind 只取 fact/hazard/recipe 三种，没有 origin、没有 trust、没有 campaign、没有日期；`src/knowledge/impact.js:309` 造出的 lesson 也没有来源字段。于是下一轮 worker 读到的"我们已知的东西"里，外部网页的句子与本仓库验证过的结论长得一模一样，正是 `2402.06363` 说的那种"把 prompt 与 data 拼在一起"的接口(§1 Introduction)。`src/research/sink.js` 只放 verified claim 不足以救，因为 claim 文本本身是从网页正文摘出来的。会错点：如果 lesson 只由 verifier 结果生成、从不含外部文本，这个通道是闭合的；但只要 rsi_research 的 sink 把带 locator 的摘录写进 `src/knowledge/store.js`，它就不闭合。

2. **"worker 没有执行注入"永远不能靠读它的输出来判断。** `2403.14720` 说这是「a structural limitation of LLMs since they operate on boundary-less streams of tokens」(§III-A Overview)，`2312.14197` 的消融显示边界意识是最吃紧的一项(§7.3. Ablation Study)，`2605.17634` 又把基于文本特征的判别打到「near-chance (AUROC 0.43–0.59)」(§1 Introduction)。所以 gate 只能采信机械证据：patch 的 diff 路径（`src/gate/scope.js` 的 parseScope 已经是这样）、verifier 的退出码、动作序列。会错点：如果指令层级那一支的训练真的在我们用的模型上落地，"读到注入但没照做"就是可观测的行为差异，而不是文本判断；`2504.18575` 的「This defense assigns responses from tools with the lowest-level privilege」(§Agentic scaffoldings.)说明这类防线在真实模型上确实存在，我的判断以它不可靠为前提。

3. **我们量的是"单次尝试是否通过"，论文说威胁在"跨调用组合"，这两件事的分辨率差一个量级。** `2604.23338` §3.4.2 那句话几乎是照着我们的 gate 写的：升级来自若干被授权动作的语义组合，而按调用逐次判权限的系统看不见它。`2607.05120` 给了具体形态——伪造的 tool call 区块能改写"我调用过什么"的历史(§IV-C Supply Chain Attack via Tool Call and Response Injection)。我们的 verifier 跑一条命令、默认 10 分钟、只留 64KB 尾部（`src/exec/verifier.js`），这个观测面看不见序列。变化：gate 要加跨尝试的动作断言，而不是再加一个按调用的检查器。会错点：如果我们每轮只有一个子 agent、一个 worktree、没有对外写权限，组合空间小到可以手工枚举，那通用算法是过度设计。

4. **静态 evalset 的分数系统性乐观，而且乐观的方向可命名。** `2602.10453` 说「current tasks are predominantly static and lack context-dependence」(§5 Benchmarks & Metrics)，`2602.03117` 认为静态任务测不出可部署性(§2.1 Benchmarks of Agent Security)。我们的 evalset 是 prompt + verify 命令对，任务之间不共享上下文，所以"某个改动让 agent 更容易被上下文带偏"这件事在分数上根本不出现。变化：需要一档上下文相关任务（同 prompt、不同污染上下文），否则 killRate 无法区分"修好了"与"没遇到"。会错点：如果我们的任务本来就都是单文件、无外部输入的代码修改，这一档没有意义——这取决于 evalset 里有多少任务会读外部材料。

5. **killRate 与 ASR 是同一种病：只要它是被优化的目标，它就会失真。** `2403.02691` 把 ASR 当主指标(§3.1 Experiment Settings)；`2510.09023` 一次破掉 12 个防御(§5 Experiments)；`2504.18575` 报出非单调的 ASR 中间档(§Mitigations.)；`2603.13026` 说近零 ASR 在自适应评估下会崩(§1 Introduction)。我们的 killRate 是被 chain 选择优化的同一个数，所以它只能做轮内排序，晋升判决必须由场外重判或 holdout 给出。会错点：如果任务里没有"对手"，killRate 的失真只是方差而不是偏置。

6. **确定性执法比模型侧训练便宜，而我们的 gate 已经是确定性的——这个性质既没写进 loop 的自我描述，也没扩到工具权限。** `2504.11703` 要求"无论模型怎么推理都成立"(§Challenges for Securing AI Agents)，并给出安全方向"只删权限"(§Deterministic Control of Policy Expansion and Narrowing)；`2503.18813` 把目标限定在不可信数据源(§3 Threat Model)，这是可以照抄的范围界定。而 `src/dispatch/session.js:162` 的 `Dispatcher.run` 在 `startActivation` 里只传 cwd、prompt、agentOptions（provider/model/effort/maxTokens）与 agentPreset，没有任何工具权限或允许列表字段——子 agent 能做什么完全由宿主默认值决定。`src/tools/index.js:1414` 的注释说写入是 opt-in、`sandbox` 只让调用者看到会改什么，说明这个语义我们已经有了，只是没强制。会错点：如果宿主默认权限本来就接近只读，这条改动的边际收益接近零；那要改的是记录（写清默认值），不是权限。

7. **我们的沙箱边界不是一个对象，是一句注释。** `2403.04960` 用非 LLM 模块做确定性收口(§IV-A 1 Hub operator)，`2504.20984` 反过来批评 IsolateGPT 把 app 输出直接交给执行管理器而不校验(§III-B New Attacks against IsolateGPT)，`2607.05120` 说明输出侧护栏对 ADI 无效(§V Effectiveness of ADI against Defenses)。我们这边 `src/exec/worktree.js` 只是每个 attempt 一个 git worktree，`src/` 里没有任何容器代码；对比 `2601.11868` 用容器做任务级隔离(§4.5 Command-Level Error Analysis)。变化：containment 应该成为任务契约里的字段（可写路径、可发起网络、可调用工具），由 gate 读它，而不是由脚本自己声明。会错点：容器不是必需品——如果 verify 在不联网的同一台机器上跑，worktree 对"写"的隔离已经够了，差别只在"读"：读到了宿主的密钥、宿主的历史 lesson、宿主其它 campaign 的证据。

8. **卡我们 loop 的可能是观测面，不是能力。** `2602.09345` §7 给出 OS 执行占时 55–60% 而内存峰均比 15.4 倍，§4.2 说负载是秒级突发且不可预测；`2601.11868` 用 LLM-judge 做命令级错误分析，而不是只看容器退出码(§4.5 Command-Level Error Analysis)。我们的失败分类里，超时与资源抖动塌进同一个 failureKind，`src/exec/verifier.js` 只保留 64KB 尾部输出，于是"被 OS 拖死"与"代码真错"在账本上不可分。变化：失败归因需要一层资源维度，否则 killRate 里混着机器噪声。会错点：如果任务都是短命单文件 patch，OS 占比远低于 55–60%，这条不成立。

## 三、这批论文之间互相矛盾的地方

1. **防线该建在模型里还是模型外，两派都用对方的失败当自己的论据。** 模型侧：`2404.13208` 用系统 > 用户 > 第三方工具输出的权限序来训练(§What Types of LLM Attacks Exist?)，`2507.02735` 用随机注入位置训练并要求「A useful prompt injection defense must provide both security and utility」(§2 Preliminaries)。模型外：`2504.11703` 说「security requires deterministic enforcement that holds regardless of how the LLM reasons, even under adversarial influence」(§Challenges for Securing AI Agents)，`2503.18813` 说能力策略「effectively prevents unintended data flows and actions」(§Defeating prompt injections with software security.)。这不是措辞差异：前者断言模型可被训练成守规矩，后者断言"无论模型怎么推理都要成立"——后者蕴含前者不构成安全边界。`2510.09023` 本来可以裁决，但它破的 12 个防御里没有一个是重训练出的指令层级模型(§5 Experiments)，所以这批材料里没有人做过这个对照。

2. **分类器到底有没有用——两篇给的是相反的量级。** `2507.15219` 在 AgentDojo 上给出可用的检测表现(§4.1 PromptArmor vs. Existing Defenses)，攻击集包含 Ignore Previous Instructions 与 System Message 这类词汇型注入；`2605.17634` 报「Prompt injection classifiers perform at near-chance (AUROC 0.43–0.59) when attacks operate through context manipulation rather than injection vocabulary」(§1 Introduction)。严格说这不是逻辑矛盾而是覆盖域不同：一个测"带注入词汇的攻击"，一个测"不带词汇、纯靠语境改写意图的攻击"。但两篇都没有在对方的域上重跑，所以拿 `2507.15219` 的数字当通用检测能力是错的，反过来用 `2605.17634` 说"分类器全废"也过头。这批里没有第三篇来合流。

3. **数据与指令能不能在接口层分开，这是真矛盾。** `2403.14720` 说这是模型的结构性缺陷：「This is a structural limitation of LLMs since they operate on boundary-less streams of tokens」(§III-A Overview)，即"分开"要求模型具备它结构上不具备的能力。`2402.06363` 说改接口就行：「We propose changing the interface to LLMs to support structured queries, instead of expecting application developers to concatenate prompts and data」(§1 Introduction)，同时承认适用范围很窄：「StruQ only protects programmatic applications that use an API or library to invoke LLMs」(§6 Discussion)。两者对"分开"指的不是一件事——一个指表征层，一个指调用契约——但结论确实相反：前者认为必须靠外部执法，后者认为接口改完就够了。`2603.19469` 站第三边：连"什么是攻击"都要相对"谁发的、什么目标、允许什么信息流"来定义(§1 Introduction)，那么"分开"本身不是接口属性而是语境属性。

4. **隔离是否必然牺牲可用性，两派给出了互相否定的经验主张。** `2403.04960` 把 hub/spoke 隔离当成可部署方案(§IV-A 1 Hub operator)，`2503.18813` 把双 LLM 的失败归因于"没做能力策略"而不是"隔离本身有代价"(§Is Dual LLM of Willison enough?)。反面是 `2602.10453` 的「Some defenses' design will destroy the agents' utility ability to solve context-dependent tasks」(§4.6 Analysis: Defense Cost)，以及它引的统计：41 篇里 34 篇把用户 prompt 或用户意图当作判定行为合法性的 ground truth(§4.6 Analysis: Defense Cost)。真正对立的是规范层：`2507.02735` 要求同时满足安全与可用，而 `2602.10453` 的材料说明在上下文相关任务上这两者目前不可同时满足。这批里没有任何一篇给出牺牲曲线。

## 四、三条我会改的
