## 落下来的东西

### `src/dispatch/stage-plan.js`（新）

`STAGES = ['plan','implement','verify']`；`stageOf(task)` 只认任务显式声明且属于这三阶段的名字（`review` 是真实存在的词、但不是本循环的阶段，**不猜**，退到 `implement`）；`harnessFor` 取配置里该阶段声明的 harness，没声明就用阶段名本身（配置有洞时丢一个阶段，比让阶段退回自己的名字更糟）；`dispatchPlan({task, config})` 在**开关关闭时返回 `null`**——不是空计划。这一条是「关时与今天逐字节一致」能成立的原因：没有下游代码能读到在这里凭空造出来的阶段。

### `session.dispatch`（配置默认）

```yaml
session:
  dispatch:
    enabled: false            # 关是默认
    stages:
      plan:      { harness: planning,     preset: null }
      implement: { harness: implementation, preset: null }
      verify:    { harness: verification, preset: null }
```

### `settings.json` 的第二个键

`src/core/settings.js` 的 `KEYS` 现在有 `plan` 和 `dispatch`，并且**每个键各自回答**：文件里只有 `plan` 时，`dispatch` 读作「从未设置」（`null`），不是 `false`。猜出来的「关」和问出来的「关」是两件事，前者会让一个旧文件悄悄决定新开关的位置。坏文件仍然一律 `null` + `reason: 'unreadable'`。

### 回合真的会用它

`src/runtime/round.js` 在算 `privileges` 的同一处算 `stagePlan`，把它传到两处：`dispatcher.run(..., { preset })`（只在该阶段**配置了** preset 时才带这个键——没有配置时不发明一个），以及 `attempt.finished` 的 `stage`/`harness` 字段（关的时候这两个键不存在，记录形状与今天相同）。

`src/dispatch/session.js` 的 `run`/`#one` 接受 `preset`，用完退回 `config.session.preset`。

### 两个胶囊

注册在 `conversation.input.left`（composer 工具行的左侧，`conversation.input.permission` 就在这一行），一条注册、两个按钮：

- **RSI**：`POST /dsh-loom/state { action: 'disable' | 'enable' }`，走的是已有的 `runtime.setEnabled`。
- **调度**：`POST /dsh-loom/state { action: 'dispatch', enabled }`，写 `settings.json` 并记审计。

两条纪律写进了代码与规格：**点击后不乐观更新**（先 POST、再重新读 `/dsh-loom/state`，只有宿主回答了才改显示），以及**说明它要做什么**（`title` 写清阶段链 `plan → implement → verify`，不是只写「调度」两个字）。

## 诚实的边界

- **本机只有一个模型族**，所以「调度」能改的是框架与 `agentPreset`，改不了「谁回答」。胶囊写「先规划流程」，不写「挑模型」，就是这个原因。跨模型自动调度要等有第二个模型族，而且那时也该由宿主的路由组来做，不该由插件二次发明。
- **spec-superflow 的 `ssf` 验证格式没有接**：那段会话读不出逐字内容，接一个只在我转述里存在的接口，等于把传闻写进契约。
- **胶囊没法在这个环境里截图**：当前宿主的 Web 端口没有在这个会话里监听（`curl 127.0.0.1:64553` 连不上），所以「我点了一下、它长这样」这句话我不能说。能说的是：bundle 通过 `tests/panel-client.test.mjs` 的 lazy-CJS 装载器挂载成功（12/12），`tests/self58/the-composer-has-two-pills.test.mjs` 钉住了注册的槽、两个按钮、两个 action 名，以及「只 require react」。
- **T3 不是依赖**，也刻意没做成依赖。
